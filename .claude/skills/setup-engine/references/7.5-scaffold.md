# /setup-engine — Section 7.5: Scaffold the Unity Project

> Part of `/setup-engine`. `SKILL.md` names when to read this file; the settings it
> resolved and the rules under its later headings still apply here.

## 7.5 Scaffold the Unity Project

**Without this step the framework produces source files no engine can open.**
`/dev-story` writes `.cs` files under the resolved code root, and the `minimal` path
advertises "four steps to running code" — but no other skill writes the Unity
project for the editor to load.

### Unity — instruct, do not fabricate

A Unity project is editor-generated and spans many files,
several of them binary or machine-specific. This repo cannot source their
correct contents, and a hand-written scaffold would be the exact failure
Section 7's sourcing rule forbids — something that looks finished and is quietly
wrong.

Tell the user, in one short block, that CCGS does not create the Unity project
and they should create it first:

- Create the project in Unity Hub at the repo root, choosing the template
  matching the 2D/3D answer from Section 2 and the version pinned in Section 3,
  then re-run `/setup-engine`.

### Folder skeleton and assemblies — create these

The Unity project itself is the editor's. The folder layout and the assembly
definitions are plain folders and JSON text files, so this step creates them,
never overwriting one that exists. The layout is mandatory and defined in
`.claude/docs/unity-folder-structure.md` (read it for the rules; this section
is only the scaffold). Run it after the Unity project exists (`Assets/` is
there); if `Assets/` is missing, report "skeleton not created, no Unity
project yet" and stop here.

Ask once: "May I create the Assets/ folder skeleton and the Core, Debugging and
Editor assembly definitions?" Then create, with `.gitkeep` in each empty folder
(Unity ignores dot-files, so no `.meta` noise):

```
Assets/Content/
Assets/Scripts/Core/
Assets/Scripts/Debugging/
Assets/Scripts/Testing/EditMode/
Assets/Scripts/Testing/PlayMode/
Assets/Scripts/Editor/
Assets/Plugins/Code/
Assets/Plugins/Content/
Assets/Settings/
Assets/Configs/
```

Also create `Assets/Resources/` (with `.gitkeep`) **only** when
`unity.asset_loading` is `resources` (Section 5.5); for `addressables`, `direct`
and unset it is not created.

`<Project>` is the project name from `project.yaml` `project.name` (else the
name in `CLAUDE.md`), with spaces and punctuation removed. Create these
assembly definitions (the test ones are `/test-setup`'s job, not this step's):

`Assets/Scripts/Core/<Project>.Core.asmdef` — gameplay logic, runtime:
```json
{
  "name": "<Project>.Core",
  "rootNamespace": "<Project>",
  "references": [],
  "autoReferenced": true
}
```

`Assets/Scripts/Debugging/<Project>.Debugging.asmdef` — opt-in, compiled only
when the `ENABLE_DEBUGGING` scripting define is set (off by default):
```json
{
  "name": "<Project>.Debugging",
  "rootNamespace": "<Project>.Debugging",
  "references": ["<Project>.Core"],
  "defineConstraints": ["ENABLE_DEBUGGING"],
  "autoReferenced": false
}
```

`Assets/Scripts/Editor/<Project>.Editor.asmdef` — editor scripts:
```json
{
  "name": "<Project>.Editor",
  "rootNamespace": "<Project>.Editor",
  "references": ["<Project>.Core"],
  "includePlatforms": ["Editor"],
  "autoReferenced": false
}
```

Add packages the scripts use (`Unity.InputSystem`, `Unity.TextMeshPro`, ...) to
`references` only once code needs them and the package is installed. The test
assemblies come from `/test-setup`. Code plugins under `Assets/Plugins/Code/<Vendor>/`
bring their own asmdefs (plus an Editor one for their `Editor/` folders).

Report the outcome in the Section 12 summary either way — already present, or
"not created, Unity requires the editor" — and, separately, whether the folder
skeleton and assemblies were created, already present or skipped — so the user leaves this
skill knowing whether a runnable project exists.

> **Deliberately not a `project.yaml` key.** An `engine.project_scaffolded` flag
> would be written here and read by nothing, which is a dead setting — the same
> writer-without-reader defect the config gates exist to catch. The filesystem is
> the source of truth: any skill that needs to know checks for
> `ProjectSettings/ProjectVersion.txt`.
